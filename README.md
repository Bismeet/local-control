## ⚠️ Important Safety Warning

> [!CAUTION]
> **`local-control` is designed to control a Windows PC.** When given goals, the agent observes the screen, plans steps, and can execute keyboard, mouse, filesystem, terminal, and browser actions.
>
> - **The LLM is untrusted:** Screenshots, OCR text, file contents, and web pages are treated as untrusted data. The LLM cannot execute code directly and can only propose strictly typed actions.
> - **Run as a standard user:** Never run `local-control` from an elevated (Administrator) command prompt. The CLI will refuse to start with administrative privileges unless explicitly forced.
> - **Compensating controls:** Because Windows lacks a lightweight input sandbox, safety relies on deterministic validation, closed action vocabularies, protected filesystem zones, rate limits, manual approvals, and emergency stop mechanisms.
> - **Recommended testing environment:** We strongly recommend running and developing `local-control` inside a dedicated Windows 11 Virtual Machine or Windows Sandbox snapshot with disposable test data.

## What is `local-control`?

`local-control` is an autonomous desktop operator that accomplishes multi-step tasks on Windows 10/11 through a cycle of:

$$\text{observe} \longrightarrow \text{reason} \longrightarrow \text{propose} \longrightarrow \text{validate} \longrightarrow \text{approve (if required)} \longrightarrow \text{execute} \longrightarrow \text{verify} \longrightarrow \text{recover/replan}$$

Unlike free-form script execution agents that run arbitrary Python or PowerShell code generated by an LLM, `local-control` uses a **strictly typed, auditable action vocabulary**. Every proposal is inspected by a deterministic safety layer before any OS interaction occurs.

## Architecture at a Glance

```
+-------------------------------------------------------------------------------+
|                             local-control process                             |
|                                                                               |
|  CLI (Typer + Rich) / Control Center (FastAPI + WebSockets)                   |
|       |                                               ^                       |
|       v                                               | events, previews      |
|  +-------------------------------------------------------------------------+  |
|  |                          AgentRunner Loop                               |  |
|  |                                                                         |  |
|  |  Observer --> Planner --> SafetyValidator --> ApprovalGate --> Executor |  |
|  |     ^            ^              |                    |             |    |  |
|  |     |            |           [Verdict]           [Decision]        v    |  |
|  |     +-------- Verifier <---------------------------------- ActionResult |  |
|  +-------------------------------------------------------------------------+  |
|       |                     |                            |                    |
|       v                     v                            v                    |
|  Observation:         Safety Layer:                Execution Tools:           |
|  - ScreenCapture      - Policy Tables (B/C/S)      - InputTool (Mouse/Keys)   |
|  - WindowManager      - PathRules (Zones)          - WindowTool               |
|  - Image downscale    - CommandRules (PowerShell)  - WaitTool                 |
|  - Optional OCR/UIA   - KillSwitch & StopToken     - FileSystemTool (Trash)   |
|                                                    - TerminalTool (Gated)     |
|                                                    - BrowserTool (Playwright) |
+-------------------------------------------------------------------------------+
                                      |
                                      v
                       Windows 10/11 Operating System
```

- **`core/`**: Pydantic v2 domain models, action vocabulary, EventBus, run directory layout, coordinate transforms.
- **`config/`**: Layered TOML and environment variable configuration via `pydantic-settings`.
- **`observation/`**: DPI-aware screen capture (`mss`), window enumeration (`pywinauto`/`pywin32`), image hashing.
- **`safety/`**: Deterministic rule classifiers (`B-*`, `C-*`, `S-*`), path zones, command filters, kill switch.
- **`execution/`**: Tool adapters for input, window management, filesystem, terminal, and browser automation.
- **`models/`**: Vision LLM provider adapters (`openai_compat`, `anthropic`, `fake`).
- **`agent/`**: The core loop (`AgentRunner`), prompt builders, response parser, verifier, and recovery ladder.

## Safety Model

Actions proposed by the planner are evaluated against deterministic policy rules:

1. **SAFE**: Read-only or trivially reversible actions inside permitted working directories (e.g., list windows, read allowed files, move mouse). Executed automatically in `assisted` mode.
2. **CONFIRM**: Significant actions requiring explicit user approval (e.g., file moves, overwrites, shell commands, closing windows). The user is prompted with an unabridged summary of the action.
3. **BLOCKED**: Dangerous or high-risk operations that are **hard-blocked** and can never be approved or overridden by configuration, autonomy mode, memory, or user prompts (e.g., entering passwords, credit card checkout, permanent file deletion, modifying system directories, running downloaded executables).

### Emergency Stop
The agent can be halted instantly via:
- **Global Hotkey:** `Ctrl+Alt+Shift+Q` (configurable)
- **Mouse Corner Failsafe:** Moving the cursor to any screen corner for > 300 ms
- **Stop File:** Creating `%LOCALAPPDATA%/local-control/STOP`
- **Control Center / Terminal:** Pressing `Ctrl+C` or clicking Stop

## Installation and Setup

### 1. Prerequisites
Ensure Python 3.11+ is installed and available in your `PATH`. We recommend using [`uv`](https://docs.astral.sh/uv/) for environment management.

### 2. Clone the Repository
```powershell
git clone https://gitlab.com/phoenix-labs-group2/local-control.git
cd local-control
```

### 3. Create Virtual Environment and Install Dependencies
```powershell
uv venv .venv
.venv\Scripts\activate
uv pip install -e ".[dev]"
```

Or using standard `pip`:
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

## Testing

The project uses `pytest` with separated test markers:

- `unit`: Pure logic (schemas, parsing, coordinate math, policy rules, run store). Runs without an active desktop.
- `integration`: Simulated agent loop using `FakeModelProvider` and virtual desktop fixtures.
- `desktop`: Real Windows screen capture and UI control (requires an interactive Windows session).
- `browser`: Playwright DOM automation tests.
- `e2e`: Full task scenarios driven by vision LLMs.

Run unit and integration tests (safe for headless CI):
```powershell
pytest -m "unit or integration"
```

Run linting and type checking:
```powershell
ruff check src/ tests/
ruff format --check src/ tests/
mypy src/local_control
```
